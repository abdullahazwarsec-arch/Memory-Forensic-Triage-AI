Memory dump of a Windows host

A RAM image (.raw / .vmem / .mem) captured from the suspect machine.

Run Volatility plugins on it and turn the plugin results into numeric counts (one row per dump).

Feature CSV — the actual input file

55 numeric columns named plugin.metric, e.g. malfind.ninjections, pslist.nproc:
pslist 5dlllist 2handles 13 ldrmodules 6malfind 4psxview 14 modules 1svcscan 7callbacks 3
• One row = one memory snapshot (one or many rows)
• Same columns as Obfuscated-MalMem2022
• Missing columns → filled with 0
• Non-numeric columns (e.g. Category, Class) are ignored
• Pre-flight check: scripts/validate_input.py

01Ingest

pd.read_csv() on the upload or sample.
Shows row/column count and a data preview.

02Select target

Pick one row for deep analysis, or click “Score all records” for a quick batch verdict on every row.

03Align features

Keep numeric columns, reorder to the model’s 55 feature_names_in_, fill gaps with 0.

04aRandom Forest classifier

random_forest_model.pkl (100 trees)
predict_proba() → P(malware) 0…1
predict() → 0 = BENIGN, 1 = MALWARE

04bIsolation Forest (zero-day layer)

isolation_forest.pkl
predict() → -1 = ANOMALY (memory pattern unlike anything seen in training), +1 = normal
Risk tier from P(malware):
NORMAL <0.40
SUSPICIOUS
HIGH ≥0.75
Both results + timestamp go into one result record that every later step reads.

05Chain of custody

Evidence ID = first 16 hex of SHA-256(file : row : time).
Verdict line appended to logs/triage_audit.log

06aSHAP

TreeExplainer on the RF.
Top 10 features that pushed the verdict toward malware (+) or benign (−), in plain English.

06bLIME

Perturbs the row around real training rows (background) and fits a local model → top human-readable rules.

07PDF report builder (ReportLab)

Evidence ID, source file/row, verdict, confidence, risk, anomaly flag + top 5 SHAP drivers + top 4 LIME rules

Triage verdict (selected row)

• Prediction: MALWARE or BENIGN
• Confidence: P(malware) as %
• Risk tier: NORMAL / SUSPICIOUS / HIGH RISK
